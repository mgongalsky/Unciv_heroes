# Редактор юнитов

Отдельное приложение Swing в модуле `devtools`, JDK 17. Работает с игровыми файлами проекта.

## Запуск

Откройте `devtools/src/main/java/com/example/devtools/UnitEditor.kt` через **Ctrl+Shift+N**
и запустите `main` зелёным треугольником. Либо после **Reload All Gradle Projects** запустите
**devtools → Tasks → application → runUnitEditor**. Задача `run` запускает то же приложение.

Для ручной конфигурации: главный класс `com.example.devtools.UnitEditor`, classpath модуля
`devtools`, рабочая директория — корень проекта. Старую конфигурацию `DesktopLauncher` замените.
Первым аргументом можно передать путь к проекту; иначе редактор ищет корень вверх от рабочей
директории или предлагает выбрать папку.

По умолчанию открывается `android/assets/jsons/Civ V - Gods & Kings/Units.json`.
Кнопка **Открыть** выбирает другой `Units.json`. Справочники читаются из соседних файлов;
объединение справочников модов с базовым набором пока не выполняется.

## Параметры

- Слева — поиск по имени или типу; справа — параметры и графика.
- **Новый** создаёт запись. **Копировать** копирует параметры под новым именем; изображения
  импортируются отдельно.
- Флажок у поля означает явное присутствие в JSON. Снятие удаляет поле, позволяя игре использовать
  значение по умолчанию, что отличается от нуля или пустой строки.
- `speed` — тактическая скорость, `movement` — перемещение на глобальной карте.
- Связи выбираются из списков; `uniques` редактируются построчно. Вложенные и неизвестные поля
  сохраняются. Имена существующих юнитов доступны только для чтения.
- **Проверить** показывает ошибки структуры и предупреждения о ссылках. Неизвестная технология,
  ресурс или повышение не блокируют сохранение: справочники редактора могут быть неполными.
  Ошибки числовых полей, структуры и имён продолжают блокировать запись.

Игровой формат читается через LibGDX, включая комментарии и разделение записей переводами строк.
При записи получается форматированный JSON без комментариев. Неизменённые значения сохраняют
типы, включая строковые числа; исходные комментарии остаются в резервной копии.

## Спрайт и иконка

Перенесите PNG/JPEG в панель или выберите файл. Изображение сразу целиком вписывается в
предпросмотр; размер исходника при этом не меняется. Шахматный фон показывает прозрачность.
Новая картинка отображается в исходных цветах. Для уже открытых иконок включён чёрный силуэт,
который можно отключить. Этот переключатель относится только к предпросмотру.

**Удалить белый фон от краёв** очищает белые и близкие к белому пиксели, соединённые с границей.
Допуск регулирует отклонение от белого. Замкнутые белые детали сохраняются, но белая часть фигуры,
соединённая с фоном, тоже может удалиться. Для сложного фона подготовьте прозрачный PNG отдельно.

**Изменить размер…** задаёт точный холст, например 100×100. Сохранение пропорций добавляет
прозрачные поля; при отключении изображение растягивается. Режим маски делает альфа-канал бинарным
по заданному порогу. Он включён по умолчанию для иконок, но не обязателен для игры: отключите его,
если нужны полупрозрачные края. Предпросмотр иконок использует ближайший пиксель, чтобы увеличение
не добавляло размытие. Цветные спрайты масштабируются со сглаживанием.

Обработка изменяет только черновик до **Сохранить**. **Отменить последнее изменение** отменяет
одну операцию. Переключение юнитов сохраняет черновики. Импорт ограничен 4 мегапикселями и
4096 пикселями по каждой стороне; упаковка также ограничена размером страницы атласа.

Пути исходников:

- Спрайт: `graphics/overrides/AbsoluteUnits/TileSets/AbsoluteUnits/Units/<имя>.png`.
  При отсутствии override читается `graphics/base/AbsoluteUnits/TileSets/AbsoluteUnits/Units`.
- Иконка: `android/Images.Construction/UnitIcons/<имя>.png`.

Изображения общие для встроенных наборов правил. Для внешнего `Units.json` импорт графики отключён.

## Цвет и фильтрация иконок в игре

Игра загружает `UnitIcons/<имя>` из `android/assets/Construction.atlas` и его PNG-страниц.
`ImageGetter.getUnitIcon` задаёт окраску: обычно чёрную, в боевом интерфейсе белую,
для некоторых показателей золотую, а в `UnitGroup` — цвет нации. Окраска умножается на RGB
текстуры: белый исходник принимает выбранный цвет, чёрный остаётся чёрным.

Поэтому редактор записывает **изменённые иконки белыми с сохранением альфа-канала**.
Чёрный предпросмотр помогает видеть их на светлом фоне. Спрайты сохраняют исходные цвета.
Предыдущая версия редактора записывала бинарную маску чёрной — это одна из причин чёрных исходников.
Неизменённые иконки и другие категории Construction автоматически не перекрашиваются.

Construction имеет формат RGBA8888 и фильтр `MipMapLinearLinear`. Это не требование бинарной маски:
полупрозрачные края поддерживаются, а игра сглаживает текстуру при отображении даже тогда,
когда редактор показывает увеличенные пиксели без сглаживания.

## Сохранение JSON и атласов

Кнопка **Сохранить** выполняет весь процесс:

1. Проверяет параметры и фиксирует текущие правки.
2. При изменении иконок готовит Construction из `android/Images.Construction`.
   При изменении спрайтов готовит AbsoluteUnits из `graphics/base/AbsoluteUnits` с наложением
   `graphics/overrides/AbsoluteUnits`. Только затронутые атласы пересобираются.
3. Упаковывает во временную папку `build/graphics/unit-editor/save-*`, проверяет страницы,
   сохранность прежних областей и наличие изменённых изображений.
4. Проверяет, что исходники и игровые файлы не изменились извне, создаёт резервную копию,
   записывает исходники, страницы, описания атласов, `Atlases.json` и `Units.json`.
   Устаревшие страницы затронутых атласов удаляются, если не принадлежат другим атласам.
5. Только после успеха снимает отметки несохранённых изменений.

Упаковка работает в фоне с окном прогресса; редактирование на это время заблокировано.
При изменении только JSON упаковка не запускается. После изменения графики **перезапустите игру**:
загруженные атласы кэшируются. Ручной repack после сохранения редактором не нужен.

Если исходников не хватает для сохранения всех прежних областей, упаковка останавливается до
замены файлов. Не используйте общий legacy repack для кастомных спрайтов: актуальные источники
AbsoluteUnits находятся в `graphics/base` и `graphics/overrides`.

## Резервные копии и восстановление

По умолчанию общие снимки находятся в `devtools/backups/save-<UUID>`; папка меняется кнопкой
**Папка бэкапов**. Снимок содержит `manifest.json`, точные прежние байты `<номер>.before`
и подготовленные новые байты `<номер>.after`. В манифесте указаны абсолютные пути назначения,
наличие прежнего файла и имена копий. Автоматически копируются все файлы, затронутые сохранением.

При обычной ошибке записи редактор откатывает уже изменённые файлы и оставляет правки в памяти.
Если во время отката файл изменился извне, редактор не затирает внешнюю правку и сообщает путь
резервной копии. Отдельные замены файлов атомарны, но вся группа не является единой атомарной
операцией при отключении питания или аварийном завершении процесса.

Статусы снимка: `prepared`, `saved`, `rolled-back`, `recovery-required`. Для ручного восстановления
закройте игру и редактор, сохраните текущие файлы отдельно и восстановите назначения из `.before`
по манифесту. Для записей `existed: false` прежнего файла не было. Не удаляйте такой файл без
проверки, что он не был позднее изменён другой программой.

**Бэкап JSON с диска** отдельно копирует все соседние JSON, а не несохранённую форму, в снимок
`<дата-время-UUID>`; `source.txt` содержит исходную папку. **Экспорт JSON** сохраняет отдельный
черновик, в том числе с ошибками, и не снимает признак несохранённых изменений.

## Ограничения игровых механизмов

Редактор добавляет запись в выбранный набор правил и подключает её графику. Набор юнитов,
попадающих после производства в гарнизон, по-прежнему ограничен именами в `BaseUnit.postBuildEvent`.
Другие юниты создаются на глобальной карте. Боевые контуры выделения также заданы для шести имён.
Новые боевые типы требуют отдельного подключения этих механизмов.

## Проверки

- `UnitDocumentTest`: формат JSON, типы, неизвестные поля, ссылки, резервные копии и конфликты.
- `UnitImagesTest`: удаление фона, масштабирование, прозрачность и бинарная маска.
- `UnitFileTransactionTest`: совместная запись, откат и сохранность внешних правок.
- `UnitEditorSaveTest`: упаковка в тестовых папках, сохранение JSON, выбор атласа и откат.
- `UnitProjectAtlasTest`: подготовка Construction и AbsoluteUnits на исходниках проекта.
  Создаёт только временные файлы под `build`; игровые файлы не заменяет.

Классы находятся в пакете `com.example.devtools.units` и запускаются через IDE.
Golden-сценарии Scene2D не охватывают Swing-приложение. Для ручной проверки импортируйте картинку,
удалите фон, измените размер, сохраните и проверьте результат после перезапуска игры.
Проверьте также отмену обработки и варианты сохранения при закрытии редактора.
