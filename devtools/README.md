# Редактор юнитов

Отдельное приложение Swing в модуле `devtools`, JDK 17. Работает с игровыми файлами, а не с копиями
из ресурсов старого прототипа.

## Запуск

1. Нажмите **Ctrl+Shift+N**, найдите `devtools/src/main/java/com/example/devtools/UnitEditor.kt` и
   откройте файл.
2. Нажмите зелёный треугольник слева от `fun main` и выберите **Run**.
3. Откроется отдельное окно редактора.

Для запуска через Gradle выполните **Reload All Gradle Projects**, затем откройте **devtools →
Tasks → application → runUnitEditor** и дважды нажмите задачу. Обычная задача `run` также запускает
редактор.

Если создаёте конфигурацию вручную: главный класс — `com.example.devtools.UnitEditor`, classpath —
модуль devtools, рабочая директория — корень проекта. Старую конфигурацию с классом DesktopLauncher
нужно заменить.

Приложение ищет корень проекта вверх от рабочей директории. Первый аргумент запуска может содержать
путь к проекту; если корень не найден, появляется диалог выбора папки.

По умолчанию открывается `android/assets/jsons/Civ V - Gods & Kings/Units.json`. Кнопка **Открыть**
позволяет выбрать другой `Units.json`. Справочники технологий, типов, ресурсов, наций и повышений
читаются из соседних файлов. Для модов с наследованием справочников объединение с базовым набором
пока не выполняется.

## Параметры

- Слева — поиск по имени или типу юнита. Справа — параметры и графика выбранного юнита.
- **Новый** создаёт запись; **Копировать** копирует параметры выбранной записи под новым уникальным
  именем. Изображения копированием параметров не переносятся: импортируйте их отдельно.
- Флажок у поля означает, что оно явно записано в JSON. Снятый флажок удаляет поле, позволяя игре
  применить значение по умолчанию. Это отличается от нуля или пустой строки.
- `speed` — тактическая скорость, `movement` — перемещение на глобальной карте; `health` и `damage`
  читаются источником определений войск.
- Связи выбираются из выпадающих списков. `uniques` редактируются построчно; `promotions` имеют
  список доступных повышений. Вложенные поля `civilopediaText` и неизвестные редактору поля
  сохраняются и доступны как отдельные элементы формы.
- **Проверить** проверяет типы и ссылки на доступные справочники. Это не полная проверка синтаксиса
  uniques игровым движком.
- Имена существующих записей доступны только для чтения: ссылки в других JSON и имена изображений не
  переименовываются автоматически.

Редактор читает игровой формат через LibGDX, включая комментарии и разделение записей переводами
строк. Сохранение выдаёт форматированный JSON без комментариев; неизменённые значения сохраняют
типы, включая строковые числа. Исходные комментарии остаются в резервной копии.

## Сохранение и резервные копии

**Сохранить** проверяет параметры, создаёт резервную копию всех соседних JSON и атомарно заменяет
`Units.json`. Если файл изменён другой программой, запись блокируется. **Экспорт JSON** позволяет
сохранить текущий документ отдельно, в том числе для сохранения черновика с ошибками; экспорт не
снимает признак несохранённых изменений.

**Бэкап JSON с диска** копирует текущие файлы на диске, а не несохранённую форму. По умолчанию
снимки хранятся в `devtools/backups/<дата-время-UUID>`. Через **Папка бэкапов** можно выбрать другой
каталог. Снимки не удаляются автоматически. `source.txt` содержит исходную папку. Для восстановления
закройте редактор и скопируйте нужные JSON из снимка в эту папку, предварительно сохранив текущие
файлы.

Изображения записываются после JSON, каждое атомарно. Предыдущие изображения сохраняются в
`<папка бэкапов>/images/<UUID>`, вместе с путём назначения. Если запись части изображений не
удалась, JSON и уже записанные изображения остаются сохранёнными, а остальные правки остаются в
редакторе для повторной попытки. Общей транзакции на весь комплект файлов нет.

## Спрайт и иконка

Во вкладке графики перенесите по одному PNG/JPEG в каждую панель либо выберите файл диалогом.
Шахматный фон показывает прозрачность. Импорт и обработка меняют только черновик до нажатия *
*Сохранить**; переключение между юнитами сохраняет черновики изображений.

**Удалить белый фон от краёв** удаляет белые/почти белые пиксели, соединённые с границей
изображения. Допуск задаёт отклонение от белого. Белые области внутри замкнутого контура
сохраняются. Белые части самой фигуры, соединённые с фоном, тоже могут удалиться: проверьте
результат и используйте однократную отмену. Это локальный алгоритм для однотонного фона, а не
нейросетевая сегментация. Для сложного фона можно импортировать заранее подготовленный прозрачный
PNG.

Размер холста и расположение фигуры сохраняются; автоматического кадрирования или масштабирования
исходника нет. Для одинакового размера в бою готовьте изображения на холсте того же размера, что и
существующие спрайты. Ограничение импорта — 4 мегапикселя, не более 4096 пикселей по каждой стороне.

Пути записи:

- Спрайт: `graphics/overrides/AbsoluteUnits/TileSets/AbsoluteUnits/Units/<имя>.png`.
- Иконка: `android/Images.Construction/UnitIcons/<имя>.png`.

Эти изображения общие для встроенных наборов правил. Для внешнего `Units.json` импорт графики
отключён, чтобы не записывать изображения мода в графику основного проекта.

## Подключение изображений к игре

Сохранение исходного PNG не пересобирает установленный атлас. Остановите игру и используйте
существующие задачи Gradle:

1. Для спрайтов: `:android:previewImages -Patlas=AbsoluteUnits`, затем
   `:android:publishImages -Ppreview=<напечатанный preview-id>`.
2. Для иконок: сначала `:android:backupImages`, затем целевая задача
   `:android:repackImages -Patlas=Construction`.
3. Перезапустите игру и проверьте результат.

Не запускайте общий legacy repack для кастомных спрайтов: актуальный AbsoluteUnits берётся из
graphics/base и graphics/overrides. Подробности: [Make-sprite-atlas](../wiki/Make-sprite-atlas.md).

## Ограничения игрового подключения новых юнитов

Новая запись добавляется в выбранный `Units.json`, и её технологические условия читаются обычным
загрузчиком правил. Но в текущей игре набор юнитов, попадающих после производства в гарнизон,
ограничен списком имён в `BaseUnit.postBuildEvent`. Другие юниты проходят стандартное создание на
глобальной карте. Редактор не меняет это правило автоматически. Контуры выделения в бою также пока
заданы для шести имён. Новые боевые типы требуют отдельного подключения этих игровых механизмов.

## Проверки

Точечные классы для запуска через IDE:

- `com.example.devtools.units.UnitDocumentTest`: игровой формат, неизвестные поля и типы, резервная
  копия, конфликт внешней записи, ссылки и копирование.
- `com.example.devtools.units.UnitImagesTest`: удаление фона, сохранение внутренних белых областей,
  допуск и прозрачность.

Существующие golden-сценарии Scene2D проверяют игровой интерфейс и не охватывают отдельное
Swing-приложение. Для ручной проверки откройте копию папки правил, измените параметр, переключите
юнита и вернитесь, создайте запись, проверьте экспорт, бэкап, перенос обоих изображений и отмену
обработки. Убедитесь, что закрытие с несохранёнными правками предлагает сохранить, отбросить или
отменить закрытие.
