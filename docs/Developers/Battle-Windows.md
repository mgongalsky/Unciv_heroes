# Battle-only для Windows

Точка входа: `com.unciv.app.desktop.DesktopLauncherBattle`.
Она открывает `BattleSandboxScreen` со сценариями из `jsons/BattleScenarios.json` и кнопкой Network battle. Локальные сценарии доступны без сервера; сетевой режим подключается к отдельному battle-server.

## Сборка

Нужны Windows x64 и полный JDK 17+ x64 с `jpackage.exe` и `jlink.exe`. Зависимости проекта должны быть доступны Gradle. Используются существующие настройки проекта, включая Android SDK при конфигурации Gradle.

Из PowerShell в корне проекта:

```powershell
.\gradlew.bat -I desktop/battle-windows.init.gradle :desktop:battleWindowsZip
```

По умолчанию упаковщик берётся из JDK, на котором запущен Gradle. Если в нём нет jpackage, укажите установленный полный JDK:

```powershell
.\gradlew.bat -I desktop/battle-windows.init.gradle :desktop:battleWindowsZip '-PbattleJdkHome=C:\Program Files\Java\jdk-17'
```

Путь выше — пример. Скрипт не скачивает Java автоматически. Для Windows64-архива используйте x64 JDK.

Включаются desktop, core, battle-protocol и зависимости runtimeClasspath. Android, iOS и серверные дистрибутивы этими задачами не собираются. Готовые атласы, изображения, шрифты и JSON включаются в JAR. Сохранения, моды, GameSettings.json и lasterror.txt из android/assets исключены.

## Результат и запуск

EXE:

```text
desktop/build/battle-windows/HeroicCivsBattle/HeroicCivsBattle.exe
```

Архив:

```text
desktop/build/distributions/HeroicCivsBattle-Windows64.zip
```

Распакуйте весь архив в доступную для записи папку и запустите EXE. Java включена. Переносите всю папку, включая app и runtime, а не один EXE. При повторной упаковке закройте ранее запущенный EXE; задача заменяет свою папку desktop/build/battle-windows.

Ранее собранный архив не получает изменения автоматически: после добавления сетевого режима нужна повторная упаковка.

## Сетевая игра

Откройте Network battle и введите адрес сервера вида `https://battle.example.com`, без `/v1`. Первый игрок загружает сценарии и создаёт комнату, второй входит по её коду. После Ready у обоих игроков открывается бой.

Для проверки на одной машине можно использовать `http://127.0.0.1:8081` и два экземпляра клиента. На разных компьютерах этот адрес указывает на собственный компьютер каждого игрока; для VPS нужен его HTTPS-адрес.

Развёртывание и ограничения восстановления описаны в [Battle-Server-Ubuntu.md](Battle-Server-Ubuntu.md).

## Ручная проверка

1. Скопируйте распакованный дистрибутив за пределы репозитория.
2. Проверьте запуск sandbox, локального боя и загрузку изображений и шрифтов.
3. В двух экземплярах клиента создайте комнату, войдите и подтвердите готовность.
4. Проверьте действия обеих сторон, восстановление кратковременного обрыва сети и завершение боя.

Проверка компиляции в IDE не создаёт EXE и не подтверждает графический запуск. Нужны отдельная упаковка и ручная проверка готового архива. Визуальные эталоны новых сетевых экранов также должны быть проверены перед выпуском.
