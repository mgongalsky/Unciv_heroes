# Battle-only для Linux x64

## Готовый пакет

Архив: `desktop/build/distributions/HeroicCivsBattle-Linux64.tar.gz`.

Размер: 118372128 байт. SHA-256:

```text
a3ac610a398749662064545c98c7d013dc6654c3b2dbcb302f502471457e7b9a
```

Это переупаковка существующего `desktop/build/battle-jar/HeroicCivsBattle.jar` от 27 октября 2026 года, а не сборка текущих исходников. Совпадение с опубликованной на сайте версией не подтверждено. Точка входа — `com.unciv.app.desktop.DesktopLauncherBattle`.

Включена Eclipse Temurin Linux x64 JRE 17.0.21+9 с AWT, лицензиями и символическими ссылками. Системная Java для запуска не требуется.

## Запуск

На Linux распакуйте весь архив и выполните:

```sh
tar -xzf HeroicCivsBattle-Linux64.tar.gz
./HeroicCivsBattle/HeroicCivsBattle.sh
```

Требуется Linux x86_64 с glibc, графической сессией, подходящими системными библиотеками, OpenGL-драйвером и шрифтами. Минимальные версии и конкретные дистрибутивы пока не проверены. ARM не входит в этот пакет.

Лаунчер выбирает рабочий каталог `$XDG_DATA_HOME/HeroicCivsBattle`, если XDG_DATA_HOME — абсолютный путь, иначе `$HOME/.local/share/HeroicCivsBattle`. Здесь хранятся настройки, сохранения и моды, отдельно от установки и обычного Unciv.

## Воспроизведение упаковки

Файлы реализации:

- `desktop/battle-linux/HeroicCivsBattle.sh` — запуск встроенной Java и выбор каталога данных.
- `desktop/battle-linux/package_linux.py` — упаковка готовых бинарных файлов на Windows или Linux с сохранением Unix-прав и ссылок; исходники игры не компилирует.

Нужен Python 3.8+ и два входных файла:

1. `desktop/build/battle-jar/HeroicCivsBattle.jar`, SHA-256 `33f5f75d1344c5431ad2b8d147b1bb92d0ad53ed2c3e696da349bb9d83b79c5c`.
2. `desktop/build/battle-linux-downloads/OpenJDK17U-jre_x64_linux_hotspot_17.0.21_9.tar.gz`, SHA-256 `9f41bf88c7900c7097444a1bdeb84146ae692bc08842490ab098063c74bf9a8a`.

Runtime получен из [релиза Eclipse Temurin](https://github.com/adoptium/temurin17-binaries/releases/tag/jdk-17.0.21%2B9); контрольная сумма сверена с метаданными API Adoptium.

Из корня репозитория:

```text
python desktop/battle-linux/package_linux.py
```

Упаковщик отказывается перезаписывать существующий результат. Перед повторным запуском перенесите прежний архив в другое место. При смене JAR или runtime нужно осознанно обновить пути и закреплённые контрольные суммы. Побайтовая идентичность повторного tar.gz не гарантируется; сверяйте контрольную сумму нового результата.

В `PACKAGE.json` внутри архива записаны SHA-256 входных файлов и лаунчера. Вложенный README отражает состояние документации до финальной проверки архива; актуальный результат приведён здесь.

## Выполненные проверки

- Контрольные суммы обоих входных файлов совпали с закреплёнными значениями.
- Контрольная сумма JAR, прочитанного из итогового архива, совпала с исходной.
- В JAR обнаружены сценарии и Linux x64-библиотеки libGDX/LWJGL.
- Java в пакете имеет формат ELF x86_64; runtime содержит `java.desktop`, `libjvm.so` и `libawt_xawt.so`.
- Права Java и лаунчера — 0755; у лаунчера LF-переносы.
- Архив содержит лицензионные материалы runtime и 148 сохранённых ссылок.

Эти проверки подтверждают состав пакета, но не его графический запуск. Проверка сборки текущих исходников в IDE также не подтверждает запуск упакованного JAR.

## Ручная приёмка перед публикацией

1. На Linux распаковать архив вне репозитория, в том числе в путь с пробелами, и запустить лаунчер из другого рабочего каталога.
2. Проверить sandbox, локальный бой, изображения, кириллицу и повторный запуск с сохранёнными настройками.
3. Проверить сетевой бой между Linux- и Windows-клиентами совместимой версии, действия обеих сторон и завершение боя.

Графический запуск и сетевая совместимость пока не проверены. Доступной настольной Linux-среды в этой сессии нет: в WSL присутствуют только служебные дистрибутивы Docker, а Docker daemon не запущен. Публикация на сайт не выполнялась.

Описание Windows-пакета и сетевого подключения: [Battle-Windows.md](Battle-Windows.md).
