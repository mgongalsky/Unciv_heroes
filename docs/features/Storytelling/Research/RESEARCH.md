# Исследование сюжетных сценариев

## Подтверждённые факты

Работа начата от `7e6007015`, ветка задачи — `feature/storytelling-scenarios`. До работы изменён `wiki/Make-sprite-atlas.md`, присутствуют пользовательские неотслеживаемые файлы, ресурсы и результаты сборок. Их не включать в коммиты задачи. Git не обнаружил AGENTS.md. rg недоступен; исследование ведётся через IDE.

- `core/src/com/unciv/logic/GameStarter.kt`: карта загружается и проверяется до создания участников. Стабильные слоты разрешаются в цивилизации, затем вызывается setTransients, создаются сценарные города, стартовые юниты и начальные ресурсы.
- `core/src/com/unciv/pure/domain/city/ScenarioCity.kt`: исходные описания имеют стабильные ID и глубокое копирование. Слоты независимы от выбранной нации.
- `core/src/com/unciv/pure/application/scenario/ValidateScenarioUseCase.kt`: проверяет ссылки, координаты, пересечения и цели победы. Локальные инварианты делегируются домену.
- `core/src/com/unciv/logic/city/InstantiateScenarioCitiesUseCase.kt`: сначала проверяет и готовит объекты, затем публикует их. Этот подход используется как образец.
- `core/src/com/unciv/logic/map/MapUnit.kt`: уже есть отображаемое имя instanceName, числовой id и чистые характеристики hero. Clone явно копирует поля; армия в старом контракте остаётся общей ссылкой. Нельзя предполагать полную изоляцию мира после clone.
- `core/src/com/unciv/pure/domain/hero/Hero.kt`: характеристики и запасы, без сценарной идентичности.
- `MapUnit.putInTile` вызывает moveThroughTile. Последний выполняет захват, эффекты местности и обновление видимости. Поэтому вызов из него без контекста не отличает движение от создания юнита.
- `core/src/com/unciv/logic/MovableUnit.kt`: движение делегируется UnitMovementAlgorithms. Его реализация ещё требует чтения.
- `TileMap.placeUnitNearTile` может выбрать соседнюю клетку; для точной сценарной расстановки это неподходящий контракт без дополнительной проверки.
- `GameStarter.addCivStartingUnits`: дополнительные войска пропускаются только при наличии и города, и юнитов. Герой без города требует отдельного сценарного правила.
- `core/src/com/unciv/logic/MapSaver.kt`: проверяет структуру при записи и чтении. `MapFormatMigration` имеет версию 3, мигрирует последовательно, отклоняет будущие версии.
- `GameInfo` имеет версию сохранения 6. Read использует рефлексию для обычных полей, а города и цивилизации восстанавливает отдельно. Clone явно копирует состояние.
- `MapEditorEditTab` содержит вложенные инструменты; Cities выключает кисть и применяет проверенный черновик командой. Слоты уже редактируются отдельно.
- `WorldScreen.update` показывает уведомления и окна. Нижний левый угол занят UnitTable; новое окно должно учитывать эту область.

## Решения

Использовать instanceName как единственный источник отображаемого имени игрового героя; добавить стабильную сценарную идентичность отдельно. Описания миссии принадлежат TileMap, прогресс — GameInfo. Не воспроизводить события из setTransients, clone или чтения сохранения. Старые карты получают пустую сюжетную конфигурацию.

Domain содержит значения, условия и переходы диалога. Application проверяет связи сценария, обрабатывает события и координирует последствия. GameInfo, Scene2D, сериализация и воспроизведение видео остаются адаптерами.

## Что требуется уточнить по коду

- Реальные точки завершения шага движения, обнаружения и начала боя, включая AI.
- Остановка многоклеточного пути и автоматизации на обязательном выборе; продолжение атаки после ответа.
- Копирование личности при улучшении/передаче юнита.
- Регистрация созданных героев и предотвращение стартовых побочных эффектов.
- Доступные платформенные возможности видео; пользователь разрешил архитектурную основу без готовых роликов.
- Проверки интерфейсов и сериализации, существующая регистрация UI playground.

Эти пункты не считаются реализованными или проверенными. Обновлять исследование по мере чтения соответствующих путей.

## Проверка рабочего интерфейса после обратной связи

Подтверждено отсутствие отображения scenarioHeroes в прежнем EditorMapHolder. Добавлен адаптер ScenarioHeroPreview без создания игрового юнита. Прежний тест обходил ввод прямым вызовом OnClickListener; теперь проверяет координаты и hit testing. ScrollPane обновляет положение содержимого при draw, поэтому проверка до кадра давала ложное падение.

Предпросмотр использует AdvanceStory на отдельном снимке. Видеосцена возвращается через стек экранов; подтверждение проверено с текстовой заменой. Прямого запуска из редактора раньше не было: добавлен Save and play с передачей сохранённой карты в NewGameScreen. Проверка дошла до настроек, полного экранного прохождения партии она не выполняет. Детали и ограничения — в [этапе 07](../Plan/STEP_07_EditorUsability.md).
