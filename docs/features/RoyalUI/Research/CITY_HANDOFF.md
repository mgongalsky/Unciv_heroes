# Исследование нового городского handoff

## Основание и состояние

Пользователь запросил изучение кода и документированный пошаговый план, предложив начать с графики. Реализация нового оформления этим исследованием не начата. Проверена ветка feature/city-sandbox, отслеживающая origin/feature/city-sandbox; присутствуют прежние посторонние изменения и неотслеживаемые бандлы. Они не включаются автоматически в изменения плана.

Отдельный запуск CitySandbox уже реализован; пользователь подтвердил, что он работает. Его BUILD и три GL-проверки прошли в предыдущей задаче. Это не новая проверка и не визуальная приёмка handoff.

Изучены документы нового бандла и selected-preset.json. Изображения и браузерный прототип в рамках планирования не просматривались; соответствие пикселей не оценивалось.

## Факты кода и последствия

| Область | Подтверждено чтением | Следствие для плана |
| --- | --- | --- |
| Тема | RoyalUi.assetRoot указывает на старый Royal Bundle; installButtons меняет default-стили и затемняет disabled целиком | Новая городская тема локальная; ткань disabled серая, золото и текст сохраняются |
| Карта | CityScreen строит CityTileGroup/TileGroupMap в ZoomableScrollPane из настоящих TileInfo | Переиспользовать renderer и координаты; ограничить квадратом, не подставлять screenshot-map |
| Экран | CityScreenContext уже отделяет разрешения от обязательного WorldScreen | Сохранить контекст при resize, переименовании и переходах; не выдавать sandbox-доступ обычной партии |
| Очередь | CityConstructions хранит MutableList<String>, inProgressConstructions — HashMap<String,Int>, queueMaxSize=10 | Нет постоянного ID отдельного проекта; прогресс не независим для одинаковых записей |
| Перестановка | raisePriority/lowerPriority меняют позиции; removeFromQueue имеет побочные эффекты для улучшений и автоматизации | Перетаскивание не реализовывать удалением и повторным addToQueue |
| Завершение | constructionComplete удаляет прогресс по имени, снимает голову, валидирует очередь; есть overflow и perpetual-проекты | Новый UI не должен самостоятельно завершать проекты или менять перенос производства |
| ETA | turnsToConstruction использует игровые CityStats и округлённое производство | Не считать ETA второй формулой в UI; нулевой/отрицательный выпуск проверить отдельно |
| Снабжение | TransferFoodUseCase и SupplyHeroMaximumUseCase в pure/application принимают CityInfo | Пакет не доказывает чистоту; новая чистая операция должна принимать значения/порт |
| Еда | Герой получает Float, город изменяется через actualAmount.toInt(); UI учитывает бонусы вместимости, transfer использует baseFoodCapacity | Проверить дробные переносы, округление и согласованность эффективной ёмкости до переноса контролов |
| Max | supplyHeroMaximum сначала выполняет перенос, затем меняет slider.value и вызывает ChangeEvent; listener вызывает transfer | Есть риск повторного применения и устаревшего foodState; требуется тест взаимодействия, дефект исполнением ещё не подтверждён |
| Армии | ArmyManager мутирует слоты напрямую; split создаёт отряд через источник с hardcoded-default; CityScreen создаёт менеджер без явного источника | Проверить характеристики разделённого отряда, входные индексы, один и тот же слот, нулевой остаток и отсутствие частичной мутации |
| Герой | CityScreen.visitingHero фиксируется при создании | Перед командой повторно определять посетителя; обработать отсутствие/замену героя |
| Статистика | CityStatsTable объединяет сводку и expanders; DetailedStatsPopup уже защищает модель копированием при отображении | Для новой открытой таблицы брать действующий расчёт, не суммировать процентные модификаторы как плоские доходы |

## Что ещё не доказано

Фактическое воспроизведение повторного переноса Max, полнота валидации ArmyInfo, точный путь автоматического снабжения при ходе и покрытие всех найденных тестов ещё не исследованы исполнением. Это обязательные пункты этапа 08, а не заявленные уже исправленные ошибки. Реальные сохранения с дубликатами очереди и сетевые отказы команд нужно проверить до игрового переключения.

Найдены тестовые файлы CityConstructionTest, CitySupplyAndDefeatTest, CityGamePersistenceTest, TransferFoodUseCaseTest, SupplyHeroMaximumUseCaseTest и CityTestSuite. Их наличие не доказывает покрытие нужных границ или независимость от движка; перед изменениями прочитать тела и дополнить адресно.

## Рекомендация

Графика первой подходит, если она собирается на настоящей карте и модели в изолированном входе. Сначала локальные компоненты и каркас, затем read-only представления, затем команды. Не копировать model.mjs и демонстрационную экономику.

Для первой версии сохранить существующую очередь и формат сохранения. UI-ключ позиции может быть временным внутри одного снимка; при изменении снимка незавершённый drag отменяется. Постоянные проектные ID и отдельный прогресс дубликатов — отдельная продуктовая и миграционная задача.
