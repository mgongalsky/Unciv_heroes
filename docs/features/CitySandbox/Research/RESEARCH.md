# Исследование отдельного запуска города

## Подтверждённые зависимости

DesktopLauncherBattle подключает отдельный экран через UncivGameParameters.initialScreenFactory после загрузки ресурсов. Этот же механизм использует DesktopLauncherCity.

CityScreen использует city.civInfo для карты, экономики, строительства и героев. Поддержка ownerOrNull в модели нейтрального города не делает этот UI независимым от цивилизации. Для текущего этапа оставлена одна настоящая CivilizationInfo в минимальном GameInfo.

До изменения CityScreen требовал WorldScreen для canChangeState, а ConstructionInfoTable и SpecialistAllocationTable читали isPlayersTurn напрямую. Теперь разрешения предоставляет CityScreenContext. Обычный путь получает его из текущего WorldScreen; автономный задаёт явно.

Экран пересоздаётся при resize, переименовании, покупке клетки, переходе к соседнему городу и page. Все эти внутренние пути используют createCityScreen и сохраняют контекст.

## Подготовка модели

Существующий CityScreenGoldenChecks предоставил образец минимальной модели с Rome, TileMap радиуса 6, городом и посещающим Warrior. Производственный CitySandbox использует аналогичную подготовку, но не вызывает loadGame. Это отдельный адаптер, без переноса тестовой инфраструктуры в игровой путь.

UncivGame.dispose сохраняет партию при ненулевом gameInfo. Песочница не присваивает свою модель этому полю. Штатный жизненный цикл приложения, ресурсов и настроек сохраняется.
