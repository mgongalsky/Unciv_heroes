# STEP 01 — Изолированное тестовое окружение

Статус: выполнен 2026-10-28.

Основа: [PLAN.md](PLAN.md), раздел 7. Следующий шаг: [STEP 02](STEP_02_Founding_Characterization.md).

## Цель

Получить повторяемую заготовку для тестов города без записи пользовательских настроек и зависимости от случайного состояния предыдущих тестов.

## Работы

1. Прочитать актуальные SerializationTests, GdxTestRunner, FakeCivilizationInfo, MapCompatibilityTests и testing hooks армии/юнита.
2. Найти реализацию json() через реальные ссылки, а не подбор имени файла.
3. Добавить конструкционный тест CityInfo(). Зафиксировать доступное состояние и границы до восстановления связей.
4. Подготовить минимальные карту, правила, участников и основателя для реального создания города.
5. Использовать существующие JUnit 4 и tests/src. Не добавлять новую библиотеку моков.
6. Для путей с I/O использовать временное изолированное хранилище. Проверить восстановление UncivGame.Current, Koin и статических testing instances после теста, включая падение.
7. Не переносить слепо setup SerializationTests, сохраняющий настройки на диск.

## Граница изменения

Основной результат — тестовая инфраструктура. Если без production-шва тест не запускается, зафиксировать конкретную зависимость и вынести минимальный шов отдельным изменением. Не заменять реальную механику основания набором пустых фейков.

## Проверки

Сборка тестового модуля и тесты новой заготовки. Проверить повторное использование заготовки и отсутствие утечки состояния между сценариями. Один seed карты не считать контролем всей случайности.

## Готово, когда

Можно воспроизводимо создать минимальную игру для теста города; пользовательские файлы не меняются; глобальное состояние восстанавливается; конструкционный тест проходит.

## Отчёт после выполнения

Добавлены файлы в `tests/src/com/unciv/testing/city/`:

- `CityConstructionTest.kt`: три теста конструктора без игры, независимости локального состояния и флага сопротивления. Коммит `c31274406`.
- `CityTestFixture.kt`: реальные GameInfo, TileMap, CityInfo и MapUnit; существующий FakeCivilizationInfo отключает скрытую загрузку правил и перехватывает уведомления. Правила читаются из игровых JSON; определения войск предоставляются через HardcodedTroopDefinitionSource.
- `CityTestFixtureTest.kt`: настоящее основание, регистрация центра и владельца, очистка при исключении.
- `CityFixtureIsolationTest.kt`: два последовательных основания, сравнение состояния и проверка восстановления глобальных зависимостей, в том числе после исключения вслед за основанием.

Сохраняются и восстанавливаются UncivGame.Current, RulesetCache, MapUnit._monsterCivInfo и currID, GameConstants._testData, ArmyInfo._defaultMaxSlots и TroopFactory.nextId. Для приватных тестовых полей используется reflection только в тестах. Созданный Koin-контекст закрывается; существующий контекст заготовка не заменяет, а отвергает такой запуск до изменения состояния. Очистка предпринимает все действия даже при ошибке одного из них.

Заготовка не вызывает GameStarter, сохранение настроек или запись игровых файлов. На этом шаге I/O ограничен чтением исходных JSON; временное хранилище для записи потребуется в шаге 04.

Проверки через IDE: BUILD успешно; CityConstructionTest — 3/3, CityTestFixtureTest — 2/2, CityFixtureIsolationTest — 1/1. Всего 6 тестов, ошибок нет. Запуск по пакету IDE не поддерживает: использовать полные имена отдельных классов. BUILD запускать без scope: модуль `tests` IDE не распознаёт.

Первоначальный GdxTestRunner упал при инициализации Mockito/CGLIB. Эти тесты успешно работают обычным JUnit без графического runner и без новой библиотеки моков. Production-код не изменялся.

Ограничения: проверено основание для выбранного окружения Rome/GnK. Это не контроль всей случайности игры: случайные ветви имён, захвата и ходов требуют отдельных сценариев или минимальных швов следующих шагов. UUID города не сравнивается между независимыми запусками. Полный жизненный цикл, сохранение и действие юнита ещё не покрыты.
