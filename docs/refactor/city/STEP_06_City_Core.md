# STEP 06 — Чистое ядро и совместимый CityInfo

Статус: не начат. Зависимость: [STEP 05](STEP_05_Extract_Founding.md).

## Цель

Выделить минимальное независимое ядро, необходимое для дальнейшего жизненного цикла и сценарного состояния.

## Работы

1. Определить типы CityId, координат, принадлежности и истории без LibGDX и legacy-классов.
2. Перенести идентичность и локальное состояние небольшими порциями; CityInfo сохраняет API и делегирует.
3. Для каждого поля определить единственный источник истины и отображение старого формата сохранения.
4. Переносить необходимые локальные вычисления с тестами на простых значениях.
5. При переносе населения отделить вычисление изменения от назначения жителей, религии и расширения территории. Сохранить порядок применения эффектов.
6. По результатам STEP_04 выбрать каноническое представление гарнизона. Проверить контракты чистой Army и её копирование.
7. Не переносить ArmyInfo с CivilizationInfo/Koin внутрь ядра.
8. Для неперенесённых систем оставить явные legacy-адаптеры.

## Граница

Новый тип владения ещё не означает, что нейтральный город разрешён в работающей игре. Не включать новый runtime-путь раньше STEP_09–10.

Не переносить всю религию и CityStats ради завершения этого шага. Не дублировать изменяемое состояние ради совместимости.

## Проверки и критерий

Обычные JUnit-тесты ядра без GdxTestRunner плюс характеристические и сериализационные проверки. Ядро можно создать и скопировать без игры; сериализация legacy-пути не изменилась случайно; чистые пакеты не импортируют инфраструктуру.

## Отчёт

Перечислить перенесённые поля, правила, оставшиеся адаптеры и каноническое состояние гарнизона.
