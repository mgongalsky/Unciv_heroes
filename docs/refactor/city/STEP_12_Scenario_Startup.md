# STEP 12 — Запуск миссии с готовыми городами

Статус: программный запуск реализован и проверен автоматически. Выбор слотов в интерфейсе относится к STEP 13. Ручная приёмка перенесена пользователем на завершение работ.

## Создание

InstantiateScenarioCitiesUseCase проверяет весь набор описаний, определения зданий/войск, явные сопоставления участников, пригодность центров, конфликты с существующими городами и территорией, вместимость гарнизонов и столицы до регистрации. Объекты сначала подготавливаются отдельно; предсказуемая ошибка описания не оставляет частично созданные города.

Города создаются без основателя, вызова CityFounding и последствий завоевания. Население и пища инициализируются без роста, религиозного давления и расширения территории. Здания и гарнизоны соответствуют описанию; стартовые подарки основания не выдаются. Пустая территория — только центр.

ID сценарного размещения используется как стабильный ID города в миссии. Независимые запуски создают независимые объекты с теми же сценарными ID. Повторное применение описаний к уже созданной миссии отклоняется.

## Правила первой реализации

- У слота с готовыми городами явно задаются одна текущая и одна исходная столица. Это могут быть разные города.
- Исходная столица отмечает реальную историю владения; участник с городом без юнитов не считается проигравшим. Существующее правило поражения цивилизации не переписывалось.
- Нейтральный город имеет фиксированный тип и не является столицей.
- Тип разрешается один раз, хранится в CityState.resolvedCityType, явно сериализуется и копируется. Получение и передача города его не меняют.
- По умолчанию FromStartingPlayer использует ключ начальной нации, Fixed — заданный ключ. Игровая семантика типа остаётся ограничением, описанным в STEP 11.
- Если у владельца готового города есть предразмещённые юниты, дополнительные стартовые отряды не выдаются.
- Иначе используется обычный набор эпохи/сложности с исключением гражданских основателей. Военные герои со способностью основания сохраняются.
- При отсутствии заданной стартовой позиции ориентиром служит текущая столица.

## Порядок запуска

Сохраняется обычная цепочка загрузки/генерации, цивилизаций и удаления чужих юнитов. GameInfo.setTransients восстанавливает связи и регистрирует предразмещённые юниты один раз; затем восстанавливаются стартовые позиции.

Сценарные города создаются перед стартовыми юнитами. Далее идут прежние политики, технологии и начальные ресурсы. Для сценарной карты после этих фаз дополнительно пересчитываются связи, видимость, ресурсы, распределение населения и статистика.

Сопоставление слота переносится непосредственно от Player к созданной цивилизации, включая случайный выбор нации. Порядок списка и сетевой ID не используются как идентичность слота.

Шов GameStarter.startNewGame(setup, saveSetup) отделяет только финальную запись пользовательских настроек. Обычная перегрузка сохраняет прежнее действие. Тесты выполняют настоящий запуск без записи пользовательских настроек.

## Отдельно обнаруженное исправление

Двойной вызов TileMap.setTransients при старте регистрировал один предразмещённый юнит дважды в списке цивилизации. Лишняя первая привязка удалена; проверка подтверждает один юнит и сохранение его позиции. Это исправление legacy-дефекта, а не требование сценарной модели.

## Проверки

Прошли:

- ScenarioCityInstantiationTest — 3 теста: точное начальное состояние и город без юнитов; отказ при ошибке во втором описании без изменений мира; оба формата сохранения, разрешённые типы и запрет повторного создания;
- ScenarioGameStarterTest — 4 теста: повторный независимый запуск сценария, обычная карта без городов, предразмещённый герой без дополнительных отрядов, пустой нейтральный город после старта;
- CityFoundingCharacterizationTest — 1 тест;
- CityCapitalStatusTest — 3 теста;
- CityPersistenceCharacterizationTest — 2 теста.

BUILD прошёл после подключения операции. Это адресные проверки, не весь тестовый набор проекта. Загрузка игры восстанавливает текущий реестр и не вызывает сценарное создание.
