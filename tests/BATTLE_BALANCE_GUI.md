# Поиск соотношений для равного боя

Запуск: Gradle → tests → application → runBattleBalance, либо BattleBalanceWindow.main с test
classpath модуля tests.

Главная таблица отвечает на вопрос: сколько защитников приходится на одного атакующего для примерно
равных шансов? Строка атакует столбец. Например, «≈ 1 : 2,50» означает около 2,5 защитников на
одного атакующего. Обратное направление рассчитывается отдельно.

Выберите Units.json, чтобы использовать сохранённые игровые характеристики. Файл перечитывается при
каждом запуске. «Набор sim-test» использует фиксированные прежние характеристики пяти войск.

## Как выполняется поиск

Размер атакующей армии фиксирован (по умолчанию 20). Число защитников увеличивается до перехода от
преимущества атаки к преимуществу защиты. Затем поиск уточняет промежуток дополнительными пробами. В
каждой пробе выполняется заданное число битв с фиксированными seeds.

Если доля побед атаки среди боёв с победителем попала в 45–55%, используется это проверенное
соотношение. Если переход резкий и проходит между соседними целыми количествами защитников, в обзоре
показывается середина интервала. Это оценка границы, а не утверждение о проверенном бое с дробным
юнитом.

Нажмите результат: вкладка подробностей показывает обе границы, реальные численности, победы сторон
и число боёв без победителя. Проценты не показываются в главной таблице.

Поиск предполагает одну убывающую границу шанса победы атаки при увеличении числа защитников.
Случайность и немонотонные эффекты могут влиять на оценку; для сравнения параметров используйте
одинаковый размер армии, seeds и достаточно битв. Результат относится к выбранному масштабу армий.

«За пределами поиска» означает, что границу не удалось охватить. Защитники проверяются от 1 до 100
размеров атакующей армии. Если даже один защитник сильнее, увеличьте размер атакующей армии (текущий
предел настройки — 20). Если и максимума защитников недостаточно, результат не экстраполируется.
«Недостаточно данных» означает отсутствие боёв с победителем в необходимой пробе.

## Прогресс и отчёты

Прогресс — завершённые направленные пары из 25. Число боёв указано отдельно; оно заранее неизвестно.
Остановка сохраняет завершённые результаты на экране, повторный запуск очищает их. Закрытие окна
останавливает дочерний процесс.

Каждый запуск создаёт папку в tests/balance-results:

- boundaries.csv — итоговые соотношения, статусы и границы;
- probes.csv — все выполненные пробы;
- parameters.txt — снимок характеристик, seeds и настройки.

Отчёты дописываются по ходу работы. После завершения кнопка «Открыть отчёт» открывает
boundaries.csv.

## Безграфический слой

BalanceBoundarySearch выполняет поиск без GUI. BattleBoundaryCli запускает реальные бои через общий
BattleBalanceSimulation и выдаёт поток результатов. GUI запускает его отдельным процессом через
BalanceWorkerProcess.startBoundary.

Аргументы BattleBoundaryCli.main: preset|путь-к-Units.json, битв на пробу, размер атакующей армии,
первый seed, папка отчётов. Старый BattleBalanceCli и sim-test сохраняют полный перебор матриц для
отдельных экспериментов.

Боевой сценарий прежний: поле 14×8, один отряд на сторону, allTilesReachable=true,
useRealMovement=false, luck=0.05, morale=0.1, максимум 300 ходов и 30 ходов без прогресса. Это
упрощённый сценарий sim-test.

Для ручной проверки запустите поиск, откройте подробности найденного отношения, затем остановите
длинный прогон и запустите повторно. Проверьте, что окно остаётся отзывчивым и показывает только
результаты текущего запуска.
